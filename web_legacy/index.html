      Set up live mode (about 5 minutes)

      1. Create a free account at maps.olakrutrim.com and create an API key.
      2. In the project folder, copy .env.example to .env and paste the key:
        OLA_MAPS_API_KEY=your-key-here
      3. Restart the server (python -m src.server) and reload this page.

      The key stays on your computer. The browser never sees it; the backend calls Ola Maps for you. Meanwhile you can use the Demo city, which works fully offline.

              How it works

              Dijkstra's algorithm, run once per transport mode

              1. Set the source's distance to 0 and every other location's distance to ∞.
              2. Push (0, source) into a min-heap (priority queue).
              3. Pop the location with the smallest tentative distance. Skip stale entries (already finalised or larger than the best known distance).
              4. Relax each edge of the current mode only: if dist[u] + km < dist[v], update dist[v], store parent[v] = (u, edge) and push the new entry.
              5. Stop when the destination is popped. Its distance is now final.
              6. Rebuild the path by following parent back from the destination, then reverse it.
              Why it is correct

              Edge weights are never negative, so when a location is popped with the smallest distance, no other path can reach it more cheaply later.

              Why not BFS?

              BFS minimises the number of legs, not total kilometres. A direct 5 km road would beat a 1 km + 1 km route, which is wrong.

              Complexity

              O((V + E) log V) time per run with a binary heap and O(V + E) space. It runs 4 times per search (once per mode).

              Illustrative sample fares, not official fares

              ModeBase farePer kmExample: 10 km

              Total fare = base fare + per-km rate × total route distance. The base fare is charged once per journey, not once per road segment. The per-km rate is constant within a mode, so the shortest route is also the cheapest. That is why Dijkstra minimises distance.

              • The city map, distances, times and fares are sample data, not live or official values.
              • Journey time = sum of connection times. Waiting, walking, transfers and traffic are not modelled.
              • Each journey uses one transport mode from start to finish (no bus → metro changes).
              • Connections are bidirectional with the same distance and time both ways.
              • The recommendation is the lowest fare. The fastest option is highlighted separately.

              Why not live Uber / Ola / Rapido / Namma Yatri prices? These companies do not offer public price APIs to other apps (Uber no longer issues the server tokens its price-estimate API needs; Ola, Rapido and Namma Yatri have no public fare API). Scraping their apps would break their terms of service. Instead, each card has a button that opens the service, where you see the exact current price.
